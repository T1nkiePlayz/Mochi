# Rust audit: themes, downloads, mods, artwork, fonts, Steam store, gamepad, Big Picture, capabilities

Scope: `themes.rs`, `modrinth.rs`, `downloads.rs`, `fonts.rs`, `game_artwork.rs`, `steam_store.rs`, `gamepad.rs`, `bigpicture.rs` (non-autostart parts), `dirsize.rs`, `main.rs`, `capabilities/*`.
Line numbers are in the fixed files. "Test" names are in the same file's `mod tests`. Verification: `cargo clippy --all-targets -- -D warnings` and `cargo test` (101 tests, was 76 before this pass counting other workers' files), `cargo audit`.

Severity totals: critical 0, high 4, medium 19, low 17 (40 defects), plus 5 hardening notes and 6 open items outside this worker's files.

## Hardening notes (not defects)

- H-1 `cargo audit` (RustSec, 552 crates): 0 vulnerabilities, 2 allowed warnings, both transitive via tauri/gtk: RUSTSEC-2024-0370 `proc-macro-error` unmaintained, RUSTSEC-2024-0429 `glib 0.18.5` unsound `VariantStrIter` (we do not use it). No action possible without a Tauri upgrade.
- H-2 `cargo clippy -W clippy::pedantic`: reviewed; only style/cast noise on 64-bit targets, nothing actionable.
- H-3 Fuzz-style tests: `random_entry_names_never_escape` (zip names), `parser_survives_hostile_shapes`, `release_dates_never_panic_on_odd_text`, `malformed_css_never_panics`, 5000-deep JSON manifest.
- H-4 Verified safe: `&s[..n]` slicing in `fonts.rs`/`steam_store.rs` always on `find()` ASCII boundaries; `crop_pixels` clamps cannot panic; no `unwrap`/`expect` on user data in owned files (only `.expect` on app build in `main`).
- H-5 `rename_enabled` still has a tiny check-then-rename window (POSIX rename overwrites); only reachable with another process racing in the user's own mods folder.
