# Shell, round 6

## What changed

- **Confirm dialogs.** `src/lib/confirm.ts` exposes `confirmAction({ title, message, confirmLabel, danger, items })`, which returns a promise. `<ConfirmHost />` is mounted once in `AppProvider` and renders `src/components/ui/ConfirmDialog.tsx`. The dialog is themed, labelled, focuses Cancel, returns focus to whatever opened it, and closes on Escape before any modal or menu underneath it does. Its `items` list names exactly what will be deleted. Every `window.confirm` call is gone: launching, removing a game, unlinking an identity, removing provider credentials, clearing cloud data, the deep-link sign-in, deleting a Tofu and clearing all app data. These actions also confirm now: clearing each data source, clearing game logs (this replaces the old two-click button), removing an authenticator or a passkey, and clearing achievements. `components/library/ConfirmDialog.tsx` re-exports the shared dialog.
- **Popover dismissal.** `src/components/ui/useDismiss.ts` closes a popover on a pointer press outside it, on Escape, when focus moves outside, and when the window loses focus. Escape closes only the innermost open popover and returns focus to its trigger. The hook uses `focusin` rather than `focusout`, so clicking inside a popover in WebKit, where clicked buttons do not take focus, never counts as leaving it. It is used by the account menu (which now has menu roles and arrow-key navigation), the notifications popover, the narrow-window nav drawer, `Select`, `VersionPicker`, the game context menu, the bulk-action popovers, the collection picker on game details and the emoji picker.
- **Achievements in Settings.** A new section, `settings/AchievementsSection.tsx`, is registered before Data & privacy.
  - **Save achievements to cloud.** This toggle is on by default and is stored per device in `mochi:achievements-cloud`. It is only active when you are signed in and Mochi cloud sync is on for the account; otherwise the toggle is disabled and the row explains why.
  - **Sync.** `state/useAchievementsCloud.ts` runs from `AchievementWatcher`. On sign-in it pulls the row from `public.achievements` and merges it into the local data, then pushes local changes 2 seconds after the last one. The merge is a union of unlocks that keeps the earliest timestamp; flags are OR-ed and lists are unioned. Steam totals are per device and never uploaded. Offline and error states appear in the section. The pure helpers are in `lib/achievementsCloud.ts`.
  - **Clear achievements data.** The cloud row is deleted first and then the local data, so a later merge cannot bring the achievements back. If cloud saving is on and the cloud cannot be reached, nothing is cleared. Achievements you still qualify for unlock again quietly.
- **Game details.**
  - **Order.** The page now runs: hero, Game information, Screenshots, Environments (Tofus), Steam achievements, Trailer, Mods.
  - **Credits.** These are no longer always "IGDB". Each screenshot's host decides its credit (`lib/imageSource.ts`: IGDB, Steam, SteamGridDB, or yours). When the screenshots come from more than one source, each set gets its own caption. Game information names its text sources, and the cover art credit comes from `artworkSource`.
  - **Gallery.** `components/details/ScreenshotGallery.tsx` lays screenshots out in justified rows. Each tile keeps its measured aspect ratio, so mixed sizes leave no holes. Images are lazy-loaded, and images that fail to load are dropped. A lightbox opens from any tile and supports the arrow keys, Home, End and Escape. It shows the position and the source, and focus returns to the tile when it closes. The old `.game-screenshot-grid` class is kept on the gallery for themes.
- The styles are in `src/styles/features/shell.css` and use only tokens. In the dev mock, Steam store details now return images of mixed sizes.

## Not verified (testing was skipped this round on request)

- No visual pass in any theme, at any window size, or on macOS/WKWebView. Only `npm run build` and `npm run lint` were run (0 errors).
- The achievements cloud sync has not been run against Supabase (the dev mock has no Supabase), and no unit tests were added for `mergeAchievements` or the image-source mapping.
- Existing vitest suites were not run. `ConfirmDialog.test.tsx` dispatches Escape on `document`, which the new window-capture listener still receives.
- Some modsys-owned code still uses its own inline two-step confirmation and was left alone to avoid conflicts: `InstalledModsPanel` file delete, ModrinthManager profile delete, and Downloads "Clear finished". Clearing notifications does not ask for confirmation.
